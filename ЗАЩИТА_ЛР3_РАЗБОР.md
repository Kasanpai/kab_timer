## 2. View, ViewGroup, виджеты

По разделу 1.1 методички:

- `android.view.View` — базовый класс графических элементов. Например, `TextView`, `Button`, `EditText`, `ImageView` — виджеты, которые являются `View` (некоторые — через цепочку наследования).
- `android.view.ViewGroup` — наследник `View`, умеет содержать дочерние элементы и располагать их. Примеры: `LinearLayout`, `FrameLayout`, `ScrollView`, `RadioGroup`.
- `LinearLayout` кладёт элементы по вертикали либо горизонтали (`orientation`).
- `FrameLayout` может размещать дочерние элементы поверх друг друга. В `activity_users.xml` он содержит `ListView` и текст пустого списка (`emptyUsersText`).
- `ScrollView` прокручивает длинную форму регистрации; у него один прямой дочерний контейнер `LinearLayout`.
- `layout_width`/`layout_height`: `match_parent` — размер по родителю, `wrap_content` — по содержимому, `dp` — единица размеров. `sp` — для размера текста.
- `android:layout_weight="1"` с `layout_height="0dp"` заставляет контейнер списка занять оставшееся вертикальное место, оставив кнопки внизу.

**Пример дерева View:**

```
LinearLayout (ViewGroup)
├── TextView (заголовок)
├── FrameLayout (ViewGroup)
│   ├── ListView (AdapterView, ViewGroup)
│   └── TextView (сообщение «Пользователей пока нет»)
├── Button («Добавить»)
├── Button («Назад»)
└── TextView (счётчик)
```

XML — декларативное описание дерева; объектам XML соответствуют Android-объекты во время выполнения.

## 3. Как Kotlin управляет XML

Код из `UsersActivity`:

```kotlin
setContentView(R.layout.activity_users)
val usersList = findViewById<ListView>(R.id.usersList)
```

- `setContentView` создаёт/подключает интерфейс из XML.
- `R` — автоматически сгенерированные идентификаторы ресурсов приложения.
- `R.layout.activity_users` — XML-макет, `R.id.usersList` — ID конкретного элемента.
- `findViewById<ListView>(...)` находит созданный объект View нужного типа.
- `val` — ссылка, которой нельзя присвоить другое значение; сам объект при этом может изменяться.
- `this` внутри Activity — ссылка на текущую Activity, её можно передавать как `Context`.
- `setOnClickListener { ... }` — регистрация callback-функции на событие нажатия. Код внутри `{ ... }` выполнится позже, при нажатии, а не сразу при установке обработчика.

## 4. Адаптер — главный вопрос лабораторной

По пунктам 1.1, 2.9, 2.10 методички: **Adapter связывает источник данных и `AdapterView`.** Сам `ListView` показывает строки и обрабатывает прокрутку/касания, а адаптер знает, сколько элементов есть и как показать каждый из них.

Фактический код:

```kotlin
private val userLabels = arrayListOf<String>()
private lateinit var adapter: ArrayAdapter<String>

val usersList = findViewById<ListView>(R.id.usersList)
adapter = ArrayAdapter(this, R.layout.item, R.id.itemContent, userLabels)
usersList.adapter = adapter
```

Разбор конструктора `ArrayAdapter(this, R.layout.item, R.id.itemContent, userLabels)`:

1. `this` — `Context` текущей Activity, доступ к ресурсам и окружению.
2. `R.layout.item` — XML-макет **одной строки** списка.
3. `R.id.itemContent` — `TextView` внутри `item.xml`, куда вставить текст.
4. `userLabels` — коллекция строк, откуда брать данные.

`onResume()` загружает сохранённых пользователей:

```kotlin
displayedUsers = UserRepository.getAll(this)
userLabels.clear()
userLabels.addAll(displayedUsers.map { user ->
    "${user.fullName}\nЛогин: ${user.login}"
})
adapter.notifyDataSetChanged()
```

- `getAll` возвращает `List<UserRecord>` — полноценные записи.
- `map` превращает записи в отображаемые строки `List<String>`.
- `clear` очищает старые строки; `addAll` добавляет новые.
- `notifyDataSetChanged()` уведомляет `ArrayAdapter`, что данные поменялись и список нужно перерисовать. **Этот вызов не сохраняет данные на диск.**
- `ListView.setOnItemClickListener { _, _, position, _ -> ... }`: `position` — индекс элемента, начиная с нуля; `_` игнорирует ненужные параметры callback.
- `usersList.emptyView = ...` — отображает заглушку, когда список пуст.

Другие адаптеры по методичке: `SimpleAdapter` — данные в картах `Map` с ключами/значениями; `SimpleCursorAdapter` — источник типа `Cursor` (например из БД). В этом проекте **только `ArrayAdapter`**.

**Чем `AdapterView` отличается от `Adapter`?** `AdapterView` — экранный контейнер, который использует адаптер (`ListView` — наследник `AdapterView`). `Adapter` — объект-посредник, обеспечивающий получение данных и создание представлений для строк.

## 5. Смена трёх картинок

Из `RegistrationActivity`:

```kotlin
private var avatarIndex = 0
private val avatars = intArrayOf(
    R.drawable.kab,
    R.drawable.sun,
    R.drawable.nut
)

avatarImage.setOnClickListener {
    avatarIndex = (avatarIndex + 1) % avatars.size
    avatarImage.setImageResource(avatars[avatarIndex])
    Log.d("Registration", "Выбран аватар: $avatarIndex")
}
```

- `intArrayOf` — массив целых чисел, здесь это ID drawable-ресурсов, а не сами картинки.
- `avatarIndex` хранит индекс выбранной картинки: 0, 1, 2.
- `(avatarIndex + 1) % 3` при 2 даёт 0, чтобы замкнуть цикл.
- `setImageResource` меняет отображаемую картинку в `ImageView`.
- Чтобы индекс пережил поворот, `onSaveInstanceState` записывает `outState.putInt("avatar_index", avatarIndex)`, а `onCreate` восстанавливает его и устанавливает ресурс.
- При успешной регистрации `avatarIndex` включается в `UserRecord`, сохраняется и затем используется в профиле.

## 6. Полная схема регистрации

1. `RegistrationActivity` вызывает `setContentView(R.layout.activity_registration)` и находит `EditText`, `RadioGroup` и `ImageView` через ID.
2. При нажатии на поле даты `DatePickerDialog` открывает календарь; месяц, полученный от Android, начинается с 0, поэтому для отображения прибавляется 1.
3. `RadioGroup` разрешает выбрать только одну кнопку, `checkedRadioButtonId` содержит ID выбранного `RadioButton`.
4. По нажатию «Зарегистрироваться» берутся `.text.toString()` из полей и выполняется проверка: пустые поля → ошибка; несовпадение паролей → ошибка; иначе создаётся `UserRecord`.
5. `UserRepository.add(this, record)` загружает существующих пользователей и проверяет уникальность логина без учёта регистра (`equals(..., ignoreCase = true)`).
6. Если логин новый, список превращается в JSON-массив (`JSONArray` из `JSONObject`), затем JSON-строка сохраняется в `SharedPreferences("registered_users")` по ключу `users`.
7. Для совместимости с профилем второй лабораторной данные последней успешной регистрации дополнительно записываются в `SharedPreferences("user_data")`. Пароль в эти записи **не сохраняется**: регистрация учебная, не реализует полноценные аккаунты/безопасный вход.
8. При регистрации из списка `intent.getBooleanExtra("from_users", false)` указывает вернуться к `UsersActivity`; из стартового экрана — к `HelloActivity`.
9. При открытии списка `UsersActivity.onResume()` снова читает сохранённых пользователей и обновляет адаптер.

## 7. Intent, Bundle, SharedPreferences: отличия

- `Intent(this, UsersActivity::class.java)` — запрос открыть другую Activity внутри приложения (явный Intent). `putExtra("kab_count", n)` передаёт значение адресату.
- `Intent(Intent.ACTION_DIAL, Uri.parse("tel:+70000000000"))` — неявный Intent, Android ищет внешнее приложение-звонилку, способное его обработать; сама программа номер **не набирает автоматически**.
- `Bundle` из `onSaveInstanceState` сохраняет временное состояние Activity, например текст полей и индекс аватара, когда Android пересоздаёт экран (например при повороте).
- `SharedPreferences` — постоянное локальное key-value-хранилище приложения; данные переживают перезапуск приложения. В проекте в `registered_users` лежит JSON-строка.
- `onCreate()` — создание/инициализация Activity; `onResume()` — экран переходит в состояние взаимодействия с пользователем (в нашем коде там обновляется список).
- `finish()` завершает текущую Activity; `startActivity()` запускает следующую.

## 8. Почему счётчик «кабачков» растёт

```kotlin
kab_Count = (savedInstanceState?.getInt("kab_count")
    ?: intent.getIntExtra("kab_count", -1)) + 1
```

`?.` — безопасный вызов, `?:` — оператор Элвиса (берёт правое значение, если слева `null`). Сначала читаем сохранённое состояние, иначе extra Intent, иначе -1. Затем `+1` — каждое создание Activity повышает счётчик, в том числе при повороте. Значение передаётся через `putExtra` при навигации.

## 9. Проблема с «Сообщить о проблеме»

`MenuActivity` использует неявный `Intent.ACTION_DIAL` и телефонный URI `tel:`. Код заменён: **прямой `startActivity(dialIntent)` внутри `try/catch(ActivityNotFoundException)`** вместо предварительной проверки `resolveActivity`, которая на Android 11+ может возвращать null из-за ограниченной видимости пакетов. Если на устройстве действительно нет звонилки, будет Toast, а в Logcat — предупреждение (`MenuActivity`). Сработает ли запуск на конкретном эмуляторе — зависит от установленных обработчиков Intent; фактический запуск нужно проверить в Android Studio.

## 10. 20 вопросов на защите — короткие правильные ответы

1. **Что такое View?** Базовый класс визуального элемента Android.
2. **Что такое ViewGroup?** Наследник View, который управляет дочерними View.
3. **Какую роль играет LinearLayout?** Размещает дочерние элементы вертикально или горизонтально.
4. **Что такое ScrollView?** Контейнер с прокруткой, у нас содержит форму регистрации.
5. **Где хранится разметка?** В `res/layout/*.xml`.
6. **Как XML отображается в Activity?** Через `setContentView(R.layout...)`.
7. **Для чего нужен `findViewById`?** Получить ссылку на конкретный View по `R.id`.
8. **Что такое `R`?** Сгенерированные ID ресурсов приложения: layout, id, drawable, string и т. д.
9. **Что такое обработчик события?** Функция, переданная, например, в `setOnClickListener`, запускаемая при нажатии.
10. **Что такое `Adapter`?** Посредник между данными и `AdapterView`, создающий/поставляющий представления строк.
11. **Что такое `AdapterView`?** Контейнер для динамических данных, например `ListView`, `GridView` или `Spinner`.
12. **Почему `item.xml` — отдельный файл?** Он задаёт оформление одной строки, которое адаптер применяет ко всем элементам.
13. **Для чего `ArrayAdapter`?** Преобразует элементы массива/списка в представления для `ListView`.
14. **Зачем `notifyDataSetChanged`?** Сообщает адаптеру, что данные изменились и нужно обновить отображение.
15. **Что делает `%` при смене аватара?** Зацикливает индекс в диапазоне 0…2.
16. **Как не теряется выбранный аватар при повороте?** Индекс сохраняется в `Bundle` и восстанавливается в `onCreate`.
17. **Как пользователь сохраняется навсегда?** `UserRepository` сериализует записи в JSON и сохраняет строку в `SharedPreferences`.
18. **Чем `Bundle` отличается от `SharedPreferences`?** Временное состояние Activity vs постоянное хранилище приложения.
19. **Как «Добавить» открывает регистрацию?** Явным Intent, дополнительно передаётся `from_users = true`.
20. **Почему это не настоящая авторизация?** Пароль не хранится и не проверяется при входе; это учебное приложение для UI и навигации.

## 11. Проверка приложения перед сдачей

- Открыть главную → меню → «Пользователи» → «Добавить».
- Проверить три картинки по кругу; повернуть устройство, убедиться, что выбор восстановлен.
- Заполнить все поля, проверить сообщения об ошибках, успешно зарегистрироваться.
- Убедиться, что пользователь появился в списке, а повторный логин отклоняется.
- Перезапустить приложение: записи должны остаться.
- Нажать пользователя: в Logcat будет его логин, на экране — Toast с ФИО.
- Нажать «Назад»: возвращается меню.
- Проверить «Сообщить о проблеме»: должна открыться звонилка, **если она установлена**; иначе появится сообщение и запись в Logcat.
- В Logcat посмотреть теги `Registration`, `UsersActivity`, `MenuActivity`, `Lifecycle`.

**Ограничения честно:** приложение не использует SQLite/Room, не создаёт реальные безопасные учётные записи; пароль не сохраняет. Полная сборка Android-приложения требует Android SDK/Android Studio; статическая сверка кода не равна запуску на эмуляторе.
